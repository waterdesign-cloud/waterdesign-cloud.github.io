成員對產品開發流程的熟悉程度不一，我先研究常見的 UX 方法，整理成循序漸進的步驟並為每一步準備範例，讓每個人都能跟著參與。

  1. 1

    產品方向研究

    比較五種影音平台類型的內容風格、觀眾行為與商業模式，團隊最初選定劇集／電影型（娛樂沉浸型）作為產品方向。

  2. 2

    使用者情境卡

    從官方 User Story 出發，以角色、時間點、裝置、任務與痛點補完使用者輪廓，讓大家先聚焦在「人」與「生活場景」，而非功能。每位成員各寫一張，作為後續的發想基礎。

  3. 3

    User Story Map

    分兩步進行：先以動詞寫下使用者的任務階段，再為每個階段補上 1～2 個具體的功能點。其中「睡眠時間提醒」的想法，後來成為核心功能之一。

  4. 4

    功能盤點與分工

    將 User Story Map 的功能點依頁面（首頁、播放頁、資訊頁、我的清單）歸類，每人負責一頁補齊功能，再以投票標出優先功能、刪去非必要項目。

  5. 5

    Flow Chart

    規劃沉浸式觀影與收藏影片兩條核心流程，涵蓋首次使用教學、睡眠時間提醒，以及非 VIP 用戶收藏整季時的升級引導。
導師回饋
沉浸體驗具發展潛力，但產品缺乏特色，難以與現有平台區隔。
團隊檢視
重新檢視市場分析後，發現「沉浸式知識平台」仍是市場空缺。
團隊調整
保留沉浸體驗並結合知識內容，將 Greon 定位為「探索 × 知識 × 沉浸體驗」的影音平台。

UI 由成員依頁面分工製作，我轉為支援成員。
在每次檢視時提供設計建議，並肯定大家的進度，讓團隊保持投入。

在團隊製作 UI 畫面時，同時間我將團隊成果統整，並補上市場背景、產品定位與平台策略，讓提案脈絡更清楚。

這次的成員背景都不一樣，對開發流程的熟悉度也不同，期中還因為產品不夠有特色而轉了方向。回頭看，最後的成果在 UX 的論述上還是不夠完整。

我學到的事

  1. 01

    組長要先穩住

    這次擔任組長，我發現這個角色最需要的是「穩」。當大家沒有方向時，要能站出來帶大家往前走，這份心理準備要先做好。

  2. 02

    先想清楚差異化

    先做競品分析、確定定位，再開始想功能，就不用做到一半才轉向。

  3. 03

    檢查要更早

    我們其實有回頭檢查，但時間點太晚，等到期中回饋才發現問題。下次會在每個階段結束前就先確認產出。
